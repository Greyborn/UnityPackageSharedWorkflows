# Unity Package Shared Workflows

Shared GitHub Actions workflow for releasing and publishing Greyborn Unity Package Manager (UPM) packages.



## UPM Release

`.github/workflows/upm-release.yml` releases and publishes a Unity Package Manager (UPM) package. On each push to `main` it:

1. Looks at the commit messages since the last `v*` tag, using [Conventional Commits](https://www.conventionalcommits.org/). `feat` commits trigger a minor release, `fix` commits a patch release, and breaking changes (`feat!:`, or a `BREAKING CHANGE:` footer) a major release. Other commit types don't trigger a release.
2. When a release is needed:
   - bumps `version` in `package.json`,
   - regenerates `CHANGELOG.md` from the full commit history,
   - sets `AssemblyFileVersion` in every `AssemblyInfo.cs` and `*.AssemblyInfo.cs` file,
   - regenerates `README.md` from the package's README template,
   - commits the changes as `chore(release): vX.Y.Z [skip ci]`, tags the commit, and pushes both,
   - creates a GitHub release with the changelog entry.
3. Publishes the version in `package.json` if the registry doesn't have it yet.

If publishing fails after a release was created, fix the cause and use **Run workflow** on the package's Actions tab. The release is already committed and tagged, so that run only publishes it.

Never set `version` in `package.json` by hand; the workflow derives it from the commits.


### Using it in a package

Copy `templates/release.yml` to `.github/workflows/release.yml` in the package repository. It expects these repository settings:

| Setting | Type | Value |
| --- | --- | --- |
| `VERDACCIO_REGISTRY` | Variable | Registry URL, such as `https://registry.example.com` |
| `VERDACCIO_USERNAME` | Variable | Registry account used to publish |
| `VERDACCIO_PASSWORD` | Secret | Password for that account |

The workflow pushes the release commit and tag to `main`, so the caller grants `permissions: contents: write`. If the organization restricts workflow permissions, that permission must be allowed there, and branch protection on `main` must let GitHub Actions push.


### README template

`README.md` is generated from the first of these that exists:

1. `.github/README.template.md` in the package
2. `.github/workflows/README.template.md` in the package (older location)
3. `actions/upm-version/templates/README.template.md` in this repository

Templates can use these placeholders:

| Placeholder | Replaced with |
| --- | --- |
| `{{displayName}}` | `displayName` from `package.json` |
| `{{packageName}}` | `name` from `package.json` |
| `{{version}}` | The version being released |
| `{{description}}` | `description` from `package.json` |
| `{{dependencies}}` | `dependencies` from `package.json`, as a list |
| `{{coverage}}` | A code coverage table from `PackageCoverageReport.json` in `.github/` or `.github/workflows/`, or `None` |


### Changelog format

The changelog is generated by [TriPSs/conventional-changelog-action](https://github.com/TriPSs/conventional-changelog-action) with the `conventionalcommits` preset, then reformatted by `actions/upm-version/lib/changelog.js`: a "Keep a Changelog" header is added, release dates are written as `— YYYY-MM-DD`, list items use `-`, and blank lines are made consistent.



## Versioning

Callers reference this repository at the `v1` tag. Compatible changes move `v1` forward; breaking changes to inputs, secrets, or behavior get a new major tag (`v2`), so existing callers keep working until they are updated.

The workflow refers to its own action as `Greyborn/UnityPackageSharedWorkflows/actions/upm-version@v1`. When creating a new major tag, update that reference to match.



## Development

The scripts use only Node.js built-in modules. Run the tests with:
